# 个人优先级规划器

## 定位

个人角色（非团队/产品）。
- **输入** = 已有任务/目标文件（目录内）+ 对话中的新任务/目标
- **处理** = 合并 → 分层定级 → 层内排序 → 容量检查 → 时间块
- **输出** = `<输入目录>/goals/` 五层文件 + 对话中的今日行动
- **原任务文件只读**，绝不修改；goals/ 是唯一写入区

## 输入定位

1. 用户指定了已有任务目录 → 以该目录为输入目录
2. 未指定 → 当前目录，找 `goals/` 分层结构（annual-*.md / quarterly-*.md / monthly-*.md / weekly-*.md / daily-*.md）
3. 未指定且当前目录无 goals/ 结构 → **全新 bootstrap 模式**
4. 指定目录内既无 goals/ 结构也无任何任务文件 → 同 bootstrap，先向用户确认一次

扫描规则（输入目录前 2 层，跳过 .git/node_modules/构建产物/隐藏目录）：
- ① `goals/` 分层文件（本 skill 的输出结构，优先级最高，视为既有规划状态）
- ② 命名文件：TODO* / todo* / tasks* / goals* / plans* / plan* / 计划* / 任务* / 目标* / 清单*（任意扩展名，.md/.txt 为主）
- ③ 任意含 `- [ ]` 或 `- [x]` 复选框的 .md/.txt 文件

## 工作流

### Step 1: 解析

把输入解析为中间结构，每项：
`{内容, 类型(目标/任务), 时限(年/季/月/周/日/无), 状态(待办/进行中/已完成/@等待), 所属(项目/目标ID), 来源(文件:行号 或 对话)}`
- `- [ ]`→待办，`- [x]`→已完成
- 标题/分组行 → 项目上下文
- 文件名/标题/正文中的日期 → 时限
- 动词开头、物理可观察 → 任务；成果性表述+时限 → 目标候选
- 向用户报告：M 个文件、N 项；无法解析的项列出并给默认理解

### Step 2: 合并

- 对话中的新任务/目标 + 解析出的存量；去重（同一件事不同表述，留更具体的，标注合并了哪些来源）
- **方向级冲突**（新目标与既有年度 One Thing 矛盾）→ 问用户，带你的推荐
- 其他冲突（超限、时间块竞争）→ 直接裁决并标注理由，用户事后审"裁剪/推迟"区

### Step 3: 分层定级

| 层 | 文件 | 硬上限 | 准入 |
|---|---|---|---|
| 年 | annual-YYYY.md | One Thing 1-3 | 过聚焦问题+极致测试；有滞后指标 |
| 季 | quarterly-YYYY-Qn.md | WIG 1-3 | 从年度派生；**每个 WIG 必须有固定周时间块+截止日期**（4DX铁律） |
| 月 | monthly-YYYY-MM.md | 里程碑 2-5 | 从 WIG 派生；有可验证完成标志 |
| 周 | weekly-YYYY-Www.md | One Thing 1 + 支撑 ≤3 | 本周对 WIG/里程碑贡献最大 |
| 日 | daily-YYYY-MM-DD.md | One Thing 1 + 支撑 ≤3 | 从周清单+Q1紧急项中选 |

定层规则：
- 有明确时限 → 归入对应层（多时限取最近）
- 年度目标候选 → 聚焦问题 + 极致测试 + 80/20 筛选
- 挂不到任何目标的任务 → 标 `服务: 无`，仍参与排序；Q4（不重要不紧急）→ 消除
- 超限项 → 进"裁剪/推迟"区，**必须写理由**，不静默丢弃

### Step 4: 层内排序

按序应用（工具定义见 [references/tools.md](references/tools.md)）：
1. **80/20**：哪些驱动年度目标的 80%？
2. **重要/紧急 2×2**：Q1 做 / Q2 排期 / Q3 批量·委托 / Q4 消除
3. **ABCDE + 3I**：A(大后果) > B(小后果) > C(无后果) > D(委托) > E(消除)
4. **影响/努力 2×2**：定执行顺序（高影响低努力=快速胜利）
5. **最丑的青蛙**：每日 One Thing = A 级中不做后果最重者
6. **时间块**：每日 One Thing 排峰值精力时段（未知→标"待填"并问一次）；WIG 固定周块写入周文件时间块总表

### Step 5: 写输出

- 位置：`<输入目录>/goals/`
- 命名：annual-YYYY.md · quarterly-YYYY-Qn.md · monthly-YYYY-MM.md · weekly-YYYY-Www.md（ISO周，`date +%G-W%V`）· daily-YYYY-MM-DD.md
- **已存在的层级文件 → 合并更新**（不盲覆盖）：
  1. 先完整读原文件
  2. 仍有效的项保留原措辞与 ID（A1/WIG-1/M1 稳定，供跨层"服务:"引用）
  3. 已完成项 → "已完成（归档）"
  4. 被裁/过期项 → "裁剪/推迟"+理由
  5. 新项按格式追加；更新元信息头（更新日/来源/峰值精力）
- **不存在 → 按模板新建**（模板见 [references/output-format.md](references/output-format.md)）
- 只有有内容的层写文件；高层缺失时低层文件头注明 `> 上游: 年度目标待定义`

### Step 6: 回今日行动（对话输出）

```
## 重排完成
**今日 One Thing**：<A1 任务> | 时间块：<HH:MM-HH:MM>
执行意图：<if-then>；5-4-3-2-1 启动；2×25min 番茄
**今日支撑**：A2 <...> / B1 <...>
**<2分钟立即做**：<...>
**本轮裁剪**：<n 项，每项一行带理由>
**文件**：goals/annual-2026.md（新建）· goals/weekly-2026-W38.md（更新）...
**待你补充**：<峰值精力时段 / 缺失的截止日期 ...>
```

## Bootstrap 模式（无既有规划）

1. **收料**：对话中的新任务/目标；最多问 3 个问题（年度想要什么 / 峰值精力时段 / 每周可固定投入的时间块），每个带默认值
2. **年度**：聚焦问题 → 2-3 候选（用户说的 + 从任务反推）→ 极致测试逐个过 → 定 1-3 个（各配滞后指标）；关注领域（健康/家庭/财务）可选
3. **季度**：从年度派生本季度 WIG 1-3，每个配固定周时间块（4DX铁律）
4. **月度**：本月里程碑 2-5（可验证完成标志）
5. **周/日**：从里程碑往下排
- 用户只想排今天/本周 → 高层标"待定义"，先把周/日做扎实，不强制全流程

## 规则

- 原任务文件只读；goals/ 是唯一写入区
- 不静默丢弃：被裁项必须有名字+理由，出现在"裁剪/推迟"
- 每层上限是硬约束：宁裁剪并标注，不超载
- 任务必须是 next action（"回复张总的合同问题"✓，"合同"✗）
- 峰值精力/截止日期未知 → 不猜，标"待填"
- 跨层一致性：周/日任务必须能挂到某个 WIG/里程碑；挂不上的标 `服务: 无` 并提醒
- 跟随用户语言（默认中文）；裁剪要直接，理由要具体
