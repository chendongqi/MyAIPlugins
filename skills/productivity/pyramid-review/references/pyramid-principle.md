# 金字塔原理审查清单

> 审查操作顺序：先提取材料自身的标题层级（编号大纲）→ 再逐项过本清单 → 记录"位置（引原文）+ 问题 + 建议"。
> 快速检查只执行文末「快速检查子集」；深度审查执行全部。

## 材料类型适配（先判断，再套清单）

| 材料类型 | 必须满足 | 可放宽 |
|---|---|---|
| 决策类（方案、预算、选型、立项） | 明确建议/结论 + 理由链 + 风险应对 | — |
| 汇报类（周报、项目进度、复盘） | 结论先行（现状 vs 目标）+ 风险 + 下一步 | SCQ 可简化 |
| 同步/通知类（信息传达、纪要） | 清晰（3C）、无歧义 | 不强求金字塔、SCQ、MECE 穷尽 |

判断不了类型时按汇报类处理。

## 一、总体结构

### 1.1 结论先行（Conclusion First）
- **标准**：第一段/第一页能直接看到核心结论或建议行动，而不是背景、过程、铺垫。
- **常见问题**：背景铺垫太长，结论出现在文末；开头全是"为了……""基于……"却不给观点。
- **修改**：把结论句移到最前，背景降为背景段。若材料确实没有结论（纯信息罗列），指出"缺少中心结论"，并给出建议补的结论句（如"建议采用 X 方案"）。

### 1.2 单一中心思想（One Message）
- **标准**：整份材料只回答一个关键问题，中心思想能用一句话说清。
- **常见问题**：多个平级结论并列（"既要拓市场，又要控成本，还要强团队"），读者不知道到底要说什么。
- **修改**：找一个能罩住全部结论的更高层主题；找不到就建议拆成多份材料。

### 1.3 分层与分组（7±2）
- **标准**：每层并列思想 ≤7 个（理想 3~5 个），超过必须再分组。
- **常见问题**：一节里 9 个平级要点，无子分组。
- **修改**：按类别分成 2~3 组，组名上提一层。

### 1.4 关键问题（Key Question）
- **标准**：材料（即使没明写）实际在回答一个明确问题，且结论就是答案。
- **常见问题**：结论答非所问，读者说不出"这份材料在回答什么问题"。
- **修改**：写出"本材料试图回答：……"，验证结论是否是该问题的直接答案；不是就调整结论或问题。

## 二、纵向关系（上下层）

### 2.1 "So what?" 链（自下而上）
- **标准**：对任一下层思想问"那又怎样？"，上层必须能接住这个回答。
- **常见问题**：某条下层思想怎么问都接不上上层（游离点、跑题点、为凑数而写）。
- **修改**：三选一——① 上层概括改写以罩住它；② 移到正确的分组；③ 删除。
- **操作**：逐条过，记下"接不上"的具体句子。

### 2.2 "Why?" 链（自上而下）
- **标准**：对任一上层思想问"凭什么这么说？"，下层必须能支撑。
- **常见问题**：结论无论据（断言）；论据不足（一个结论只有一条孤证）。
- **修改**：补论据（数据/事实/案例）；补不出来就建议弱化结论措辞。

### 2.3 归纳/演绎正确性
- **标准**：
  - 归纳：上层 = 下层的**概括**，必须"罩得住"下面每一条。
  - 演绎：上层 = 下层推导的**结论**，前提成立则结论必然成立。
- **常见问题**：
  - 假归纳：概括罩不住某条下层（第 3 条不属于这个概括）。
  - 假演绎：前提和结论其实是并列关系，不是推导关系。
  - 演绎出现在中间层（难读，读者要自己心算前提）。
- **修改**：假归纳 → 检查分组是否错误；假演绎 → 改归纳（提炼一个概括句）；中间层演绎 → 改归纳。

### 2.4 问答结构
- **标准**：每层思想都是对上层所提问题的回答。
- **操作**：给每一层写出它回答的"问题"，检查答案是否切题。

## 三、横向关系（同层并列项）

### 3.1 MECE（相互独立、完全穷尽）
- **标准**：
  - 相互独立：并列项之间不重叠。
  - 完全穷尽：并列项合起来覆盖该层问题的完整讨论。
- **常见问题**：
  - 重叠："加强线上推广 + 拓展线上渠道"（同一件事说两遍）。
  - 遗漏：讨论"营收下滑"只分析了产品，没分析渠道/竞争/价格。
- **修改**：
  - 重叠 → 合并，或明确边界（一个管 X，另一个管 Y）。
  - 遗漏 → 先想"讨论这个问题的完整维度有哪些"再补。常用维度：内部/外部、过去/现在/未来、成本/收益/风险、人/货/场、产品/渠道/推广/价格、存量/增量。
- **注意**：穷尽不是绝对。作者有意不讨论某维度时，材料里应有说明（如"渠道端无变化，不展开"）；没有说明才算问题。

### 3.2 三种排序（只能选一种）
- **标准**：并列项按且仅按以下之一排列：
  1. **时间顺序**：有先后且不可换（步骤 1→2→3、发生过程）。
  2. **结构顺序**：整体的各部分，可换（按地区/部门/模块/环节）。
  3. **程度顺序**：按重要性/大小排序，可换但次序表强调（最重要→最次要）。
- **常见问题**：顺序混用（前两条按时间、第三条按重要性、最后按结构）。
- **判断法**：
  - 交换位置会破坏逻辑（步骤断链）→ 时间
  - 交换位置不影响意思 → 结构
  - 交换可以，但次序决定强调重点 → 程度
- **修改**：按一种逻辑重排；原序号称"时间"但项间没有时间关系 → 改结构顺序并说明结构依据。

### 3.3 同组同类（同一逻辑范畴）
- **标准**：并列项属于同一层级的概念、同一类型的事物。
- **常见问题**（苹果梨混放）：
  - "成本、效率、团队精神"（前两个是管理指标，第三个是文化）。
  - "北京、上海、华东地区"（前两个是城市，第三个是区域）。
  - "提升产品质量 + 加强员工培训"（一个是结果，一个是手段）。
- **修改**：提升概念层级（"团队精神"→"组织与文化建设"）或移到正确的组。

## 四、开场（SCQ）

### 4.1 SCQ 完整性
- **标准**：开场包含四件：
  - **S**ituation：读者认同、无争议的共同背景。
  - **C**omplication：打破背景的变化/矛盾/冲突。
  - **Q**uestion：由 S+C 自然引出的关键问题。
  - Q 的**答案** = 材料的中心结论。
- **常见问题**：
  - 缺 S：读者不知道背景。
  - 缺 C：没有冲突，材料显得没存在必要。
  - 缺 Q：直接抛结论，读者不知道"我为什么要关心"。
  - S 跑题：背景与主题无关，纯凑字数。
- **修改**：补缺失件；S 和 C 改写到能自然推出 Q 的程度。

### 4.2 开场长度
- **标准**：结论出现之前，口头汇报 ≤1~3 分钟，书面 ≤1~2 段。
- **修改**：S 压缩到共同共识层面；C 的细节（数据、经过）移到正文。

## 五、标题与表达

### 5.1 观点标题（Action Title）
- **标准**：每节标题是带观点的完整句子，不是主题词。
  - ❌ "利润分析"
  - ✅ "利润下滑主因是原材料涨价，A 产品线毛利率下降 8 个百分点"
- **修改**：把标题改写成"结论 + 核心证据"。

### 5.2 标题链
- **标准**：只按顺序读全部标题（不看正文），能串成一个自洽的完整论证（材料的"微型版"）。
- **操作**：提取全部标题连读，检查前一条标题的"So what"是否被下一条标题接住。
- **修改**：重写断链处的标题。

### 5.3 一段一点
- **标准**：每段/每个 bullet 只表达一个观点。
- **常见问题**：一个 bullet 里混着"原因 + 现象 + 建议"。
- **修改**：拆成多个 bullet；建议类内容移到专门的"建议/下一步"部分。

### 5.4 3C（Clear, Concise, Concrete）
- **标准**：
  - Clear：无模糊词（"相对""基本""部分""适当""尽快"）。
  - Concise：无冗余修饰、无重复表述。
  - Concrete：能量化就量化（"显著提升"→"提升 23%"；"部分客户"→"约 40% 客户"）。
- **修改**：模糊词替换为具体表述；删冗余；数字给基准（同比/环比/对比目标）。

## 六、数据与论证

### 6.1 先结论后数据
- **标准**：每个数据块前面有一句结论（数据是结论的论据，不是主角）。
- **常见问题**：一堆数据罗列，没有观点，读者要自己猜想说明什么。
- **修改**：数据前加一句"这组数据说明……"。

### 6.2 事实与观点区分
- **标准**：事实（可验证的数据/事件）与观点（推断/判断）可区分；观点必须有事实支撑。
- **常见问题**：观点当事实说（"市场已经饱和了"——依据是什么？）。
- **修改**：观点补支撑事实，或弱化措辞（"从……来看，我们判断……"）。

## 快速检查子集（只做 3 项）

1. **结论先行**（1.1）：核心结论是否在第一段/第一页？
2. **同层同类 + 单一排序**（3.3 + 3.2）：并列项是否同类？排序是否是单一逻辑？
3. **MECE**（3.1）：并列项是否重叠或遗漏关键维度？

## 严重度判定

- 🔴 **大问题**：影响读者理解核心结论 / 逻辑断裂——结论不先行、So what 断链、MECE 断裂、游离点、假归纳/假演绎。
- 🟡 **中问题**：影响顺畅度与说服力——排序混用、SCQ 不完整、标题非观点句、模糊表述、数据无结论。
- 🟢 **建议**：润色类——冗余词、表达优化、措辞改进。
- **拿不准时降一级**（宁轻勿重）。

## 审查纪律

- 先列结构再审查，避免边读边判。
- 每个问题必须能定位到原文（引短句）。
- 不存在的优点不硬夸；清单不适用的条目直接跳过（如通知类材料不查 SCQ），不要为了凑数硬找问题。
- 问题建议给出**具体改法**（"改为 X""拆成 A/B/C""删除此句"），禁止只说"不 MECE"。
