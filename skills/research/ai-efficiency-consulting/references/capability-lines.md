## 3. 能力线

### 3.1 七条能力线

阶段不是单一指标,而是由多条能力线共同决定。每条线打 **L0–L4**,L 与 A 对应(L2 对应 A2 水平,依此类推)。

| 线 | 回答的问题 |
|---|---|
| 1 工具与 Skill | 做法有没有被固化成可复用的能力 |
| 2 Workflow 与协作 | 多步骤、多角色的衔接由谁完成 |
| 3 数据与知识 | Agent 能拿到什么上下文,可信不可信 |
| 4 基建与平台 | 能力跑在什么上、是否统一管理 |
| 5 治理与安全 | 权限、审计、质量闸口、回滚 |
| 6 组织与人 | 谁负责、谁有能力 |
| 7 度量与价值 | 能否算清投入和产出 |

### 3.2 每条线各等级的描述(同时是评分锚点)

**线 1:工具与 Skill**

| 等级 | 描述 |
|---|---|
| L0 | 无 AI 工具用于该业务 |
| L1 | 个人自行使用通用 AI 工具(对话、编码助手),做法留在个人 |
| L2 | 有统一入口;常用做法已沉淀为 Skill 并有人维护 |
| L3 | Skill 有组织级治理:版本、评测、准入、安全扫描、使用度量;可跨团队复用 |
| L4 | 依据结果数据自动评估和迭代 Skill |

**线 2:Workflow 与协作**

| 等级 | 描述 |
|---|---|
| L0 | 无 |
| L1 | 人手工串联多个 AI 工具,人负责衔接 |
| L2 | Agent 承接单个多步任务,人通过对话驱动 |
| L3 | 多 Agent 按定义的流程协作,有人在回路的确认点和质量闸口;改进靠人的经验 |
| L4 | 流程依据业务结果自动调整,部分场景闭环自治 |

**线 3:数据与知识**

| 等级 | 描述 |
|---|---|
| L0 | 业务数据和知识 AI 不可读(纸质、口头、封闭系统),或没有被记录 |
| L1 | 人手动复制上下文给 AI |
| L2 | Agent 能主动检索;已有最小可用的接入链路;业务结果数据开始连通 |
| L3 | 过程留痕、经验显性化;有入库治理(版本、分层、责任人、质量门禁);语义层(术语或本体)可用 |
| L4 | 结果数据闭环、外部数据自动回流;语义层可生长 |

**线 4:基建与平台**

| 等级 | 描述 |
|---|---|
| L0 | 无 |
| L1 | 无统一,各人自备工具 |
| L2 | 个人级:各自的 agent 工具加插件,未统一管理 |
| L3 | 组织级:统一规范、运行时、入口,有模型网关 |
| L4 | 进化型:评测、在线实验、自动归因、自动迭代 |

**线 5:治理与安全**

| 等级 | 描述 |
|---|---|
| L0 | 无规则 |
| L1 | 靠个人自觉和口头约定 |
| L2 | 有基本使用规范和数据分级 |
| L3 | 规范遵循、过程可追溯、权限与审计、质量闸口 |
| L4 | 行为审计、权限边界、兜底回滚、量化考核均自动化 |

**线 6:组织与人**

| 等级 | 描述 |
|---|---|
| L0 | 无人负责 |
| L1 | 个别爱好者自发使用 |
| L2 | 基本全员 M0;该业务范围有明确的业务 owner |
| L3 | 基本全员达到 M1;设置 Skill、Workflow、MCP、知识库、评测五类 Owner;职能按业务目标而非岗位划分 |
| L4 | 业务小组织(人人是一人公司式的超级个体);有 M2 级内部 FDE |

**线 7:度量与价值**

| 等级 | 描述 |
|---|---|
| L0 | 无 |
| L1 | 凭感觉或零散问卷 |
| L2 | 有使用量和 token 成本数据 |
| L3 | 消耗 → 归因 → 产出 → 效能 → 价值的链路完整,能算 ROI(节省工时 × 人力单价 − token 成本)÷ token 成本 |
| L4 | 度量结果驱动资源分配和模型路由等决策 |

> 来源说明:A1–A4 在数据、基建、语义、治理、素养上的描述来自阶段模型;其余各线的等级描述,以及七条线的划分,是我据阶段模型、转型路线图和课程资料综合整理。

### 3.3 阶段判定规则

**门控线**:线 1、2、3、4、5。线 6、7 是支撑线,不参与门控,但会产生风险提示。

判定:
1. 线 1 为 L0 → 该业务范围判为 **A0**。
2. 否则从 A1 起向上判:**判为 An,要求所有门控线都 ≥ n**(A1 只要求线 1 ≥ L1)。取满足条件的最高 n。
3. **风险提示**:支撑线低于当前阶段 2 级以上,标红。例如阶段已判 A3,但度量线只有 L1,则说明投入产出没人看,容易被砍。
4. **瓶颈线**:门控线中低于"下一阶段"要求的那几条,就是升到下一阶段的缺口。

这是我设计的判定规则,目的是让"阶段"可复核:任何一个判定都能回答"是哪条线卡住了"。它对应"跳过治理会重复踩坑"的教训——治理线(线 5)和数据线(线 3)没到位,阶段就上不去。

### 3.4 示例

某业务范围各线得分:线 1 = L2,线 2 = L1,线 3 = L2,线 4 = L2,线 5 = L1,线 6 = L2,线 7 = L1。
- 线 1 ≥ L1 → 不是 A0。
- 判 A2 需要门控线都 ≥ 2,线 2 = L1、线 5 = L1 不满足 → 不是 A2。
- 判 A1 只要线 1 ≥ L1 → **判为 A1**。
- 升到 A2 的缺口(瓶颈线):线 2(Workflow 与协作)、线 5(治理与安全)。
- 风险提示:线 7 为 L1,与线 1 持平,暂不标红。
