## 4. 数据与接入

诊断要下钻到数据层:这个业务**缺什么数据、数据在哪些系统、怎么接入、接到哪个平台**。平台的差异见第 5 章,这一章讲数据本身。

### 4.1 从业务任务到数据需求

1. **拆任务**:该业务范围里,人或 Agent 要完成哪些任务?
2. **找决策点**:每个任务要做哪些判断?
3. **推信息需求**:做每个判断需要哪些信息?
4. **落到数据清单**:这些信息对应哪些具体数据?

### 4.2 数据清单字段

| 字段 | 含义 |
|---|---|
| 数据名称 | 如"缺陷记录""需求文档""设备参数表" |
| 类型 | 结构化事实、半结构化文档、非结构化内容、代码、规范与规则、概念与关系 |
| 所在系统 | 具体系统名称 |
| 责任人 | 谁负责这份数据 |
| 可达性 | 0 不存在或没被记录;1 存在但只能人工导出;2 有 API 或只读通道;3 已接入 AI 平台 |
| 质量 | 完整性、准确性、一致性、时效性 |
| 敏感级别 | 公开 / 内部 / 敏感 / 机密 |
| 更新频率 | 实时 / 日 / 月 / 一次性 |
| 权限模型 | 谁能看什么,权限由谁管理 |

### 4.3 缺口分类(诊断结论的格式)

| 缺口类型 | 含义 | 典型动作 |
|---|---|---|
| **不存在** | 业务过程没有被记录("没有被记录的业务,对 AI 不存在") | 先让业务留痕:会议转写、审批记录、人给 Agent 的反馈、结构化录入 |
| **不可达** | 存在,但程序读不到 | 选接入方式并解决权限(见 4.5) |
| **不可用** | 读得到,但质量差或格式不对 | 解析(OCR/ASR/表格)、清洗、入库治理 |
| **不够用** | 可用,但缺语义或关联,Agent 仍然看不懂 | 术语表、业务语义层、关联关系 |

一个业务范围的数据缺口清单就是这四类的列表,每一项再配上接入方案。

### 4.4 按数据类型选处理方式

| 数据类型 | 例子 | 处理方式 | 反模式 |
|---|---|---|---|
| 结构化事实 | 多维表格、工单字段、业务数据库 | 精确查询(API 或 SQL);业务库加语义层 | 用向量检索查状态、数量类事实 |
| 半结构化文档 | 文档平台、Wiki、接口文档 | 按标题层级或块树切分;向量加关键词混合检索;保留目录路径元数据 | 固定 token 切分 |
| 非结构化内容 | PPT、PDF、图片、会议录音 | 先多模态解析(OCR、ASR),再摘要、切分、索引 | 原始图片、表格直接进向量库 |
| 代码 | Git 仓库 | 静态分析、符号索引、调用图 | 当普通文档切块 |
| 概念与关系 | 需求—设计—代码—测试—缺陷追溯 | 类型化图或关联表 | 靠相似度猜关系 |
| 规范与规则 | 编码规范、ADR、接口契约 | Schema 加可执行校验 | 只写成散文 |

### 4.5 接入方式库

下面是通用接入方式。选哪种取决于"系统有什么、数据怎么用、要多实时"。

| 方式 | 适用 | 优点 | 取舍与风险 |
|---|---|---|---|
| **官方 API / 开放平台** | 成熟的 SaaS 或有开放接口的系统(文档平台、工单、代码托管) | 实时、权限可控、字段稳定 | 有配额和字段限制;需要开发;权限范围常是难点 |
| **数据库只读(只读账号或只读副本)** | 没有 API 的业务库(如 ERP) | 数据全、不依赖厂商接口 | 表字段晦涩,需要语义层才能被 Agent 用对;要防止影响生产性能;必须只读加脱敏 |
| **数据仓库 / 数据湖** | 企业已有清洗好的数仓 | 已治理、口径统一 | 有延迟;口径可能与业务现场不一致 |
| **文件导出 / 批量导入** | 一次性或低频的资料(规范、历史报告) | 最简单 | 版本管理差,容易过期;靠人工触发 |
| **连接器加同步(定时或 Webhook 增量)** | 需要持续更新的文档和工单 | 常态化、可自动 | 要设计增量键、幂等、版本戳;权限映射要验证 |
| **MCP 服务** | 在 agent 工具里让模型按需调用外部系统 | 与具体 agent 工具解耦,标准化 | 工具描述设计、权限透传、返回内容大小控制;由业务系统自带或自建网关 |
| **CLI / 脚本封装** | 个人级、小范围、快速验证 | 实现快 | 难以治理和复用,不适合组织级 |
| **事件 / 消息流** | 需要对变更实时响应(如状态变更触发动作) | 实时、解耦 | 需要消息基础设施;事件语义要治理 |
| **会议 / 音视频转写** | 隐性知识(会议、评审、访谈) | 能捕获没被记录的内容 | 转写错误;说话人与权限;隐私合规 |
| **界面自动化(RPA)** | 无 API 无数据库入口的遗留系统 | 能触达封闭系统 | 脆弱、维护成本高;最后兜底,不作首选 |

**选择规则(初稿)**

| 条件 | 优先方式 |
|---|---|
| 系统有稳定开放 API,且需要持续更新 | 连接器加同步 |
| 系统是业务库,无 API,数据结构化 | 数据库只读加业务语义层 |
| 企业已有数仓且口径可信 | 先走数仓 |
| 资料量小、很少变动 | 文件导入加 Skill 或知识库 |
| 目标平台自身不带知识基建,系统有 MCP | 直接接 MCP |
| 目标平台自身不带知识基建,系统无 MCP | 自建 MCP 网关或知识服务(见第 5 章) |
| 隐性知识未被记录 | 先做会议转写,再进入知识流程 |
| 前面都不可行 | 界面自动化,并标明风险 |

### 4.6 接入前提清单

| 项 | 要问清楚 |
|---|---|
| **权限** | 用什么账号(个人 / 服务账号)?能访问的范围是什么?审批流程要多久?是否能做到"按调用者权限透传",而不是用一个万能账号 |
| **同步** | 多久更新一次?增量靠什么键?删除和修改如何处理?过期内容如何降权 |
| **解析** | 有没有扫描件、图片、录音、复杂表格?解析质量如何 |
| **安全合规** | 数据分级;是否能出企业网络;是否允许送外部模型;脱敏要求;审计要求 |
| **稳定性** | 接口限流;系统维护窗口;失败重试与告警 |
| **责任** | 接入后谁负责维护这条链路和这份数据 |

**权限是最常见的卡点**:许多项目卡在拿不到足够的数据源权限,而不是技术实现。诊断时要把"权限是否已解决"作为单独一项问清楚。

| 数据项 | 所在系统 | 缺口类型 | 接入方式 | 目标平台上的落地做法 | 前提与风险 | 优先级 |
|---|---|---|---|---|---|---|
