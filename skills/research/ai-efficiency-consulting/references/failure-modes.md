## 9. 组织、治理与失败模式

### 9.1 组织与角色

- **五类 Owner**:Skill、Workflow、MCP、知识库、评测;另需业务流程与评测 Owner。
- **每个业务范围必须有业务 owner**,且要懂 AI 也懂业务。
- 内部 FDE(M2 级)负责语义层和数据基建。
- 知识责任人在业务范围立项时绑定;知识健康度进考核。
- 工具线和人线并行:买工具与培养人同步推进。
- 从一个业务单元(BU)的一个业务范围开始。

### 9.2 横向要求

| 项 | 要点 |
|---|---|
| 权限与安全 | 权限过滤由系统层保证,不靠提示词;agent 调用按调用者权限透传;最小权限、数据分级、审计 |
| 评估 | 尽早建评测集;分层评测;既测检索也测业务结果;人工标注先测一致率 |
| 人机协同 | 低置信度、冲突、新类型必须人工确认;AI 建议与人工认证分开存 |
| 访问方式 | 不直接暴露向量库;不做一个万能搜索工具;工具描述写得像提示词 |
| 次序 | 先有显式规范和后置验证,再提高 AI 自主度 |

### 9.3 失败模式与诊断信号

| 失败模式 | 在诊断中如何识别 |
|---|---|
| 个人效率之和被当成组织效率 | 线 1 高,但线 2、3、5 低:各人各用,衔接靠人 |
| 跳过治理直接扩展 | 线 5、线 3 低于 L2,但已复制到其他范围 |
| 各范围各自为政 | 同类知识多处重复且口径不一;没有统一牵头 |
| 提前建设 | 建了平台、图谱或本体,但没有业务范围提出需求,或使用率很低 |
| 一期追求本体 | 语义层有投入,但治理线和评测都低 |
| 知识没有责任人 | 线 6 为 L0–L1 |
| 只测检索、不测业务结果 | 评测集只含检索指标 |
| 数据源权限未解决 | 接入长期卡在授权 |
| 把所有数据塞进向量库 | 结构化问题答错率高 |
| 只上线不运营 | 度量线低,准确率随时间下滑 |
| 抽取结果未经审核即使用或回写生产 | 图谱无认证状态字段 |
| 先提高自主度、后补规范 | agent 权限大,但无后置验证 |
| 买工具不培养人 | 线 6 低于线 1 两级以上 |
