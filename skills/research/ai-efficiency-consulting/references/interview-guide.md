## 7. 诊断方法

### 7.1 流程

```
开场:确认业务范围清单和访谈目标
  ↓
逐个范围:按七条能力线提问 → 要求证据 → 追问
  ↓
数据层下钻:任务 → 数据清单 → 缺口 → 接入方式
  ↓
确认目标平台:类型判断 → 接入路线 → 要补的基建
  ↓
打分:每线 L0–L4,附证据;判定阶段;找出瓶颈线
  ↓
输出:阶段路径图、能力热力图、数据缺口图
```

### 7.2 访谈提纲(按能力线)

每条线给出核心问题、要的证据,以及需要追问的信号。

**线 1 工具与 Skill**
- 问:这个业务现在谁在用 AI?用什么?做什么?有没有统一入口?常用的做法有没有写下来?
- 证据:工具清单、使用数据、Skill 清单、示例。
- 追问信号:"大家都在用"但说不出具体场景 → 可能只是零星使用;有 Skill 但没人维护 → 不算 L2。

**线 2 Workflow 与协作**
- 问:一件完整的事,从开始到结束经过几步?哪些是人在转交?哪些是 AI 完成?出错了谁发现?
- 证据:流程图、一个实际案例的全程记录。
- 追问信号:全流程自动,但每一步由人点击触发 → 仍是人在做中台。

**线 3 数据与知识**
- 问:AI 做这件事需要的资料在哪?它能自己取到吗?资料是否过期?有没有统一的叫法?
- 证据:数据清单、抽样问答、抽查库内重复和旧版本。
- 追问信号:"我们有知识库"但没人维护 → 治理不达标;结构化问题答错 → 可能把结构化数据塞进了向量库。

**线 4 基建与平台**
- 问:AI 能力跑在什么上?是各人自己装还是统一提供?模型是怎么接入的?有没有网关?
- 证据:架构图、平台清单。
- 追问信号:多套平台互相不通 → 重复建设风险。

**线 5 治理与安全**
- 问:谁能让 AI 访问什么数据?AI 的操作有没有记录?出错能不能撤回?有没有质量闸口?
- 证据:权限设计、审计日志、规范文档。
- 追问信号:"靠提示词约束" → 不算权限治理。

**线 6 组织与人**
- 问:这个业务有没有明确的负责人?谁维护 Skill 和知识?考核里有没有体现?
- 证据:责任人清单、岗位说明、考核条目。

**线 7 度量与价值**
- 问:怎么知道 AI 带来了多少改变?成本怎么统计?
- 证据:使用和成本报表、效能对比数据。
- 追问信号:只有问卷满意度 → L1。

### 7.3 评分规则

1. **每个分数必须有证据**(文档、截图、系统数据、抽样结果、案例)。
2. 只有受访者口述、没有证据的:**最高给口述水平低一级,并标"待证实"**。
3. 同一条线有多个互相矛盾的说法,取较低的,并记录矛盾。
4. 评分后用 3.3 的规则判定阶段,并列出瓶颈线。
5. **抽样验证优先于自述**:能现场抽几个问题试一试、抽几份资料看看,比问十个问题更可靠。

### 7.4 诊断结果的数据结构

skill 内部用一份结构化数据驱动所有图形,诊断与方案共用它。字段设计如下(JSON,示意):

```json
{
  "client": "客户名称",
  "scopes": [
    {
      "id": "scope-1",
      "name": "业务范围名称",
      "interviewed": true,
      "scores": { "tools": 2, "workflow": 1, "data": 2, "infra": 2, "governance": 1, "org": 2, "metrics": 1 },
      "evidence": { "tools": ["证据描述"], "data": ["..."] },
      "unverified": ["tools"],
      "stage": "A1",
      "bottlenecks": ["workflow", "governance"],
      "risks": [],
      "target_stage": "A3",
      "platform": { "name": "Wolfpack", "type": "I" },
      "data_items": [
        {
          "name": "缺陷记录",
          "type": "structured",
          "system": "工单系统",
          "gap": "unreachable",
          "access": "connector+sync",
          "platform_action": "新建导入配置",
          "risk": "权限范围待确认",
          "priority": 1
        }
      ]
    }
  ]
}
```

约定:
- `interviewed: false` 的范围固定为 `stage: "A0"`,图上用特殊样式标"未访谈"。
- `gap` 取值:`missing`(不存在)、`unreachable`(不可达)、`unusable`(不可用)、`insufficient`(不够用)。
- `platform.type` 取 `I` 或 `II`,II 类要再给 `route`(`a` / `b` / `c`)。

### 7.5 可视化

**图 1:阶段路径图**
- 横轴 A0 → A4,在阶段之间标出**分水岭**(谁做中台、跨过人人协作、变好的来源)。
- 每个业务范围一行,标出**当前阶段**(实心标记)和**目标阶段**(空心标记)。
- 未访谈的范围显示在 A0,并用虚线或灰色标"未访谈,默认 A0"。
- 在标记旁标瓶颈线。

**图 2:能力热力图**
- 行是业务范围,列是七条能力线,单元格显示 L0–L4,用色阶表示。
- 门控线和支撑线在视觉上区分。支撑线低于阶段 2 级以上标风险。

**图 3:数据缺口与接入图**
- 每个业务范围一块:左边是数据项,中间标缺口类型,右边是接入方式和目标平台。
- 用颜色区分缺口类型。
