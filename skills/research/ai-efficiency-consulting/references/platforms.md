## 5. 平台与接入模式

### 5.1 核心区分:平台是否自带知识基建

业务范围要接入的 AI 平台由受访者决定。指南不预设平台,只判断**该平台是否已自带知识工程基建**,因为这决定了数据接入的做法和要补的基建。

| 类型 | 特征 | 举例 |
|---|---|---|
| **I 自带知识基建** | 平台内已有知识库、记忆、技能注入、检索、权限过滤 | Wolfpack |
| **II 不带知识基建** | 平台是 agent 工具本身,外部数据主要通过 MCP 或 Skill 接入 | Claude Code、WorkBuddy(依据见 5.4,WorkBuddy 的企业版是否自带知识库待核实) |

### 5.2 类型 I:自带基建的接入做法

接入新数据的路径:
1. **新建导入配置(profile)**:把数据源的字段映射到平台的知识模型,定义同步方式和过滤条件。
2. **增加连接器**:平台没有的数据源,开发新的连接器。
3. **通过入库接口写入**:脚本或工作流把数据推入平台。

特点:治理、检索、权限、注入已有,新数据主要是**映射和连接**的工作,成本较低。要关注的是平台**缺了什么**(例如没有版本关系、冲突识别、质量门禁),这些要在平台上补,而不是在数据侧补。

### 5.3 类型 II:不带基建的接入做法

数据要进入 agent 的上下文,有三条路:

| 路线 | 做法 | 适用 | 成本 |
|---|---|---|---|
| **a. 业务系统自带 MCP** | 系统本身(官方或第三方)提供 MCP 服务,agent 工具直接接 | 系统已有 MCP,数据按需调用即可 | 低;但 MCP 的权限、返回内容、稳定性要评估 |
| **b. 自建知识基建 / MCP 网关** | 自建一个服务,统一做接入、治理、检索、权限,对外暴露为 MCP | 需要跨系统检索、治理、语义层,或系统无 MCP | **高**:等于做一套类型 I 平台的能力 |
| **c. Skill / 文件下发** | 把规范、手册等稳定内容写成 Skill 或随工作目录下发 | 资料量小、变动少 | 最低;不适合动态数据 |

**决策思路**:
- 先问:数据是动态的还是稳定的?是单系统还是需要跨系统?需不需要治理和语义?
- 稳定且量小 → c。
- 动态,单系统,系统已有 MCP → a。
- 需要跨系统、治理、语义,或系统没有 MCP → b,这时要明确告诉客户:**这是在建知识基建,不是配一个插件**,周期和责任人都要按基建来规划。

**混合做法(推导,非来源给出)**:agent 工具作为用户入口,背后的知识服务由一个自带基建的平台提供,通过 MCP 或 Skill 暴露。适用于客户已选定某个 agent 工具,但又需要一套统一的知识基建的情况。

### 5.4 已查到的平台事实

> 来源是联网检索的摘要和文档站标题,WorkBuddy 的官方页面均未能读取,因此只收录多个来源一致的内容,并标明确定程度。

| 平台 | 已确认 | 确定程度 | 未能确认 |
|---|---|---|---|
| **WorkBuddy(腾讯)** | 桌面端 AI 智能体;内置多种大模型及主流 MCP Server 与 Skills 技能包;在用户授权下可调用本地应用、系统功能和文件系统 | 多个来源一致 | 自带知识库、长期记忆能力 |
| | Skill 为 `SKILL.md` 形式的可复用工作流包,默认目录 `~/.workbuddy/skills/`;配置中有 `mcp_servers` 连接 MCP | 多个来源一致,部分来自社区教程 | 接入外部业务系统时的权限透传、数据隔离 |
| | 企业版提供智能体管控平台、智能体开发平台、技能在控制台统一管理与复用、可观测、企业级安全;与企业微信、腾讯文档深度集成 | 厂商发布稿摘要 | 企业版是否自带知识库、接入业务系统的具体方式 |
| **Claude Code** | 通过 MCP 连接外部数据源;Skill、CLAUDE.md、hooks 机制;无自带企业知识库 | 已知产品能力 | 具体企业版管控能力需按客户版本核实 |
| **Wolfpack** | 自带知识库(KB Gateway)、记忆(Mem0)、skill 动态注入、任务派发时注入知识;新增数据靠导入配置或连接器;agent 访问现为 skill 加 REST | 本仓库代码调研 | 通过 MCP 访问受 daemon 启动参数限制,需改造 |

**据此归类**:Wolfpack 属类型 I;Claude Code 属类型 II;WorkBuddy 目前按类型 II 处理,但它的企业版是否自带知识库待核实,核实前不写成结论。其他通用 agent 工具(如 Cursor、Copilot 一类)大概率也属类型 II,这是推断,需要逐个核实。

### 5.5 平台对比维度

诊断时让受访者确认其选择的平台,并按下表判断后果:

| 维度 | 要问什么 |
|---|---|
| 知识基建 | 自带?缺什么? |
| 数据接入扩展方式 | profile、连接器、MCP、Skill、还是别的 |
| 权限透传 | 能否按调用者身份访问数据源 |
| 记忆 | 有无跨会话记忆;是否分层 |
| Skill 与工作流 | 是否支持;如何治理 |
| 部署与合规 | 公有云、私有化、可否用国产模型、数据是否出境 |
| 管控与度量 | 有无审计、用量统计、可观测 |
| 生态 | 与企业现有办公、研发系统是否集成 |
| 成本 | 授权方式、按量计费 |

### 5.6 输出

对每个业务范围:选了哪个平台 → 它属于哪个类型 → 数据接入走哪条路线 → 平台要补哪些基建 → 这些基建由谁建、什么时候建。
