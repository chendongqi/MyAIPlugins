## 8. Roadmap 与方案设计

### 8.1 Roadmap 的组成

对每个业务范围:
- **泳道**:按能力线或按工作流拆成并行泳道。
- **任务**:每个任务有名称、所属线、前置依赖、负责角色、产出、验收标准。
- **里程碑**:取阶段门槛(例如"治理规则能自动执行""评测集覆盖核心场景"),不取日期。
- **关键路径**:标出会拖慢整体的依赖链。
- **时间轴**:用相对周期和顾问填入的实际约束(人力、起止时间)排布。**指南不提供默认周期**,因为没有可靠数据;`知识工程线`里的 S0–S5 周期仅是估计,见附录。

### 8.2 通用依赖规则

| 规则 | 含义 |
|---|---|
| 权限先于接入 | 数据源权限没解决,接入不能开工 |
| 评测先于优化 | 没有评测集,不要启动任何优化、图谱或语义建设 |
| 接入先于治理 | 先有数据才能治理;但治理规则先于扩展 |
| 治理先于语义 | 治理线未到 L2,不建本体和图谱 |
| 样板先于复制 | 一个业务范围跑通,才复制到下一个 |
| 平台选定先于规模化 | 平台不确定,不批量做 Skill 和 Workflow |
| 规范先于自主度 | 先有显式规范与后置验证,再放权 |

### 8.3 各阶段的典型任务(跨阶段升级)

| 升级 | 典型任务 |
|---|---|
| A0 → A1 | 选工具、开通账号、做基础培训、识别已在自发使用的人、确立业务 owner |
| A1 → A2 | 统一入口;把高频做法写成 Skill;接通第一批数据源让 Agent 能自己检索;建立基本使用规范和数据分级;采集使用与成本数据 |
| A2 → A3 | 入库治理(版本、分层、责任人、质量门禁);过程留痕与经验显性化;Workflow 与人在回路的确认点;组织级运行时与模型网关;权限与审计;术语表与语义层;设置五类 Owner;度量链路 |
| A3 → A4 | 评测与在线实验;自动归因;结果数据闭环与外部数据回流;自动迭代 Skill;行为审计、权限边界、兜底回滚;可生长语义层 |

按业务范围类型的路径差异见 6.2:数据查询类先做业务库语义层,文档问答类先做治理,追溯类才考虑图谱。

### 8.4 方案文档结构(每个业务范围一份)

1. **现状**:当前阶段、七线得分、证据、瓶颈线、风险。
2. **目标**:目标阶段、验收指标(含业务结果,不只是检索指标)。
3. **数据与接入**:数据缺口清单与接入方案表(4.7)。
4. **平台与基建**:所选平台、类型、接入路线、要补的基建、责任人。
5. **Roadmap**:泳道、任务、依赖、里程碑、关键路径。
6. **组织与资源**:业务 owner、五类 Owner、所需人力(由顾问估算)。
7. **风险与对策**:来自失败模式(第 9 章)的对应项。
8. **验收与度量**:评测集、指标、反馈闭环。
