## 2. 阶段模型(A0–A4)

### 2.1 阶段定义

| 阶段 | 谁是"中台" | 定义 | 变好的来源 |
|---|---|---|---|
| **A0** | — | **该业务范围内没有任何 AI 工具被用于其工作**。(A0 是本指南新增的起点,原阶段模型从 A1 起。) | — |
| **A1** | 人 | 人操作各种 AI 工具,人是中台;高手和新手之间没有沟通渠道,做法留在个人身上。零星的个人使用属于 A1 的低端 | 个人摸索 |
| **A2** | Agent | Agent 是中台,人只面对一个对话窗口(聊天软件、机器人、统一的 agent 入口);Agent 能主动检索所需上下文;业务结果数据开始连通 | 人给 Agent 补规范、补知识 |
| **A3** | Agent 之间 | Agent 之间自行协作,不再受人与人协作的瓶颈约束;过程留痕、经验显性化;语义层(术语、本体)让 Agent 原生就知道业务含义 | **人的经验** |
| **A4** | Agent 自我进化 | Agent 依据业务结果和外部数据自我进化,超越人的经验;结果数据闭环,语义层可生长 | **业务结果与外部数据** |

两个大阶段:**个人提效(A1–A2)**,仍依赖人与人协作;**组织提效(A3–A4)**,Agent 之间协作不再受人人协作约束。

### 2.2 分水岭(判阶段时最该看的)

| 跨越 | 分水岭 | 一句话判据 |
|---|---|---|
| A0 → A1 | AI 进入业务 | 有没有人在用 AI 做这个业务的活 |
| A1 → A2 | **谁做中台:人 → Agent** | 完成一件事,是人在多个工具之间搬运和拼装,还是对一个 Agent 说一件事、它去取上下文并执行 |
| A2 → A3 | **跨过人与人协作** | 多个步骤或多个角色之间的衔接,是靠人转交,还是 Agent 之间自己协作 |
| A3 → A4 | **变好的来源:人的经验 → 业务结果** | Agent 的改进是人看了结果再去改,还是系统依据结果数据自己迭代 |

### 2.3 常见误判

| 误判 | 实际情况 |
|---|---|
| 买了很多 AI 工具就判 A2 | 工具多但人还是中台,仍是 A1 |
| 做了一个知识库就判 A3 | 知识库只让 Agent 能检索,属于 A2 的特征;A3 要有过程留痕、语义层和 Agent 间协作 |
| 有 Workflow 就判 A3 | 如果 Workflow 的每一步仍由人触发和转交,只是自动化脚本,不是 Agent 协作 |
| 有评测就判 A4 | 评测只是人看结果;A4 要求结果数据反过来驱动迭代,并有回滚和审计兜底 |
| 用的人多就判高 | 渗透率反映广度,阶段反映深度;两者要分开看 |

A4 对多数企业是方向性目标,可以先做**部分场景的闭环进化**。

### 2.4 个人素养 M0–M2(辅助)

| 级别 | 含义 |
|---|---|
| M0 | 会用 AI,A2 基本要求全员具备 |
| M1 | AI Native Leader,能把经验、SOP、打法沉淀为 Skill,推动组织级 Agent 化 |
| M2 | 内部 FDE(前向部署工程师),负责 AI 基建、语义层、数据基建;百人团队约 1–2 人 |
