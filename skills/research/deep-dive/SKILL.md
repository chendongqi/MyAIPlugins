# Deep Dive:深度而非广度

目标:同一件事做得更深,不扩大范围。禁止靠"多列几点、多覆盖几个方面"充当深入。

## 流程

### 1. 校准(先于任何研究,必须输出)

针对用户的话题/提示词,逐条回答,每条要具体到该领域,不写泛泛之谈:

1. **顶级从业者会做、但用户没要求的事**:该领域的资深人士面对同样问题,会多做哪一步?(例:性能问题先测量再谈优化;读论文先复现再评价;做竞品分析先看对方的真实日志/账单/招聘而非官网)
2. **最原始的材料**:他们从什么出发,而不是从已被消化过的摘要出发?给出具体来源类型与获取路径。见 [references/raw-materials.md](references/raw-materials.md)。
3. **具体的方法与工具**:点名方法、命令、框架、库,不写"进行分析"。
4. **外部验证物**:除了"我(AI)"和"你(用户)"之外,什么能证明结果对?(可运行的代码/测试、实测数据、一手来源的原文、官方基准、可复现的实验、领域专家可核对的可证伪预测、第三方独立来源的交叉印证)

信息不足以回答某条时,先用工具(搜索、读文件、跑命令)查,查不到再向用户提一个最关键的问题;不要一次问多个。

### 2. 重写提示词

基于四问产出重写版,放在校准之后展示。重写版必须:
- 保持原任务范围不变,只加深度(不引入新子话题)
- 明确指定:起始原始材料、使用的方法/工具、产出形态、验证物与"算对"的判据
- 写出判据的反面:什么结果出现就说明结论错了(可证伪条件)

展示重写版后直接执行,除非用户喊停或重写改变了原意。

### 3. 按重写版执行

- **从原始材料开始**:先读/取/跑一手材料,再看二手解读;二手来源只用于定位与对照,不当依据。
- **先做再说**:能运行的就运行(代码、查询、测量、复现),把观察到的输出当证据,而不是凭记忆推断。
- **记录证据链**:每个关键结论后跟其来源(文件:行、URL+原文片段、命令+输出)。区分"亲自观察到""来源声称""我推断"三档。
- **主动找反例**:对核心结论至少尝试一次推翻它,并写明尝试结果。
- 工作量大且可拆分时,用 Agent 并行取材,但综合与判断由自己完成。

### 4. 外部验证

执行第 1 步确定的验证物。能自己跑的就跑并给出结果;不能跑的(需要专家、硬件、付费数据)明确列为"待外部验证",并给出验证者该怎么核对的最小步骤。禁止用"看起来合理"代替验证。

### 5. 交付格式

按此顺序,简洁:
1. **结论**(一两段,含置信度)
2. **证据**(按档位标注:观察/来源声称/推断)
3. **验证结果**(已通过/未通过/待外部验证,各自依据)
4. **仍不确定与下一步最值钱的一件事**

不写与问题无关的背景科普;不堆砌来源列表。

## 反模式

- 把"更多角度/更多条目"当成深入
- 引用综述、博客、AI 摘要作为主要依据
- 只给结论不给可复核路径
- 验证物是"我再检查了一遍"
